# Plan 5.2: Mobile QA & Table Conversion

## Objective
Finalize the mobile-first responsive design by auditing touch targets, converting data tables to card layouts on narrow screens, and verifying core flows (job creation, kanban) on mobile viewports.

## Context
- .gsd/ROADMAP.md
- MungkhudShop/src/assets/css/mobile.css
- MungkhudShop/src/assets/css/design-system.css

## Tasks

<task type="auto">
  <name>Touch Target & Layout Audit</name>
  <files>
    MungkhudShop/src/assets/css/mobile.css
    MungkhudShop/src/assets/css/components.css
  </files>
  <action>
    - Add CSS rules in `mobile.css` or `design-system.css` to ensure all `.btn`, `input`, `select`, and `.tab-btn` elements have a minimum height of `44px` for touch-friendliness on screens `< 768px`.
    - Ensure `.form-row-2` and `.form-row-4` collapse correctly to `1fr` on mobile to prevent horizontal overflow.
  </action>
  <verify>Inspect CSS changes for touch target minimums.</verify>
  <done>All interactive elements are easy to tap on mobile devices.</done>
</task>

<task type="auto">
  <name>Table to Card Conversion</name>
  <files>
    MungkhudShop/src/assets/css/mobile.css
  </files>
  <action>
    - Implement a CSS `@media (max-width: 768px)` block for `.data-grid` tables.
    - The rule should hide `thead`, make `tr` display as `block` or `flex` with card styling (border, padding, margin-bottom).
    - `td` elements should display as `block` or `flex` and use `::before` pseudo-elements reading a `data-label` attribute to show the column header.
    - Update `customer-history.js`, `daily-summary.js`, and `job-data.js` to add `data-label` to table cells if necessary.
  </action>
  <verify>Check `.data-grid` behavior on mobile viewports.</verify>
  <done>Tables are fully readable on narrow screens without horizontal scrolling.</done>
</task>

## Success Criteria
- [ ] Minimum 44px touch targets on buttons and inputs.
- [ ] Tables convert to stacked cards on screens < 768px.
- [ ] No horizontal scrolling required on main forms and reports.
