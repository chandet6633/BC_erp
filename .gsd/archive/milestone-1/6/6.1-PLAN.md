# Plan 6.1: Mechanic Portal — Page Scaffold & Active Jobs Dashboard

## Objective
Create a new `mechanic` tool page in the Portal following the established multi-page HTML pattern. The page will show a mechanic their active assigned jobs, allowing them to see job details at a glance from their phone.

## Context
- Portal uses multi-page HTML (one HTML file + one JS logic file per page).
- Each page imports `pocketbase.js`, `authService.js`, `ui.js`, `helpers.js`, then its own `logic.js`.
- Data access: `window.pb.collection('jobs').getFullList({ filter: ... })`.
- Roles are checked via `window.AuthService.getUser()` and `.requireRole()`.
- New pages must be registered in `registry.js` (TOOLS array) and `vite.config.js` (rollupOptions.input).

  <action>
    - Copy `_tool-template/` → `mechanic/`.
    - In `index.html`: set title to "หน้างานช่าง | BC Auto", add Material Icons link, load `../../services/pocketbase.js`, `../../services/authService.js`, `../../components/ui.js`, `../../utils/helpers.js`, then `./logic.js`. Add `../../assets/js/app-shell.js` and `../../assets/css/app-shell.css`.

      - A "งานวันนี้" (Today's Jobs) section: cards grid showing assigned jobs where `lead_mechanic_id` or `helper_mechanic_ids` matches the logged-in user's mechanic record.

      - Role check: `window.AuthService.requireRole(['mechanic', 'sa', 'owner', 'manager', 'admin'])`.
      - Get current user → find matching mechanic record from `mechanics` collection.
      - Fetch jobs where `status != 'cancelled'` and `status != 'closed'` (active jobs only).
      - Filter client-side: jobs where `lead_mechanic_id === myId` OR `helper_mechanic_ids` contains `myId`.
      - Render as mobile-friendly cards (no tables — this is a phone-first page).
  </action>
